# Claude 연결 도구

Node.js와 설치·인증된 Claude Code CLI를 사용한다. 추가 패키지와 API 키 파일은 만들지 않는다. 명령은 워크스페이스 최상위 기준이다.

```powershell
node 도구/claude-bridge/bridge.mjs status
node 도구/claude-bridge/bridge.mjs send --file 협의/ai-collaboration/두번째-메시지.txt --from codex --task ai-collaboration
node 도구/claude-bridge/bridge.mjs history
node --check 도구/claude-bridge/bridge.mjs
node --test 도구/claude-bridge/bridge.test.mjs
```

`send`는 UTF-8 메시지 파일을 읽어 CLI의 표준 입력으로 전달한다. 메시지를 셸 명령으로 해석하지 않는다. 최초 호출에서 전용 세션 ID를 만들고 성공한 이후에는 명시적 `--resume`으로 같은 세션을 이어간다. 현재 열려 있는 다른 Claude 창과 동일한 세션을 제어하는 도구는 아니다.

연결은 [프로그램 방식 실행 공식 안내](https://code.claude.com/docs/en/headless)를 따르며, CLI의 기존 인증과 조직 정책을 사용한다. 권한 우회 옵션은 사용하지 않는다. 대화용 호출에 내장 도구와 MCP 서버를 제공하지 않으므로 검토할 파일 본문과 검증 결과를 메시지에 직접 포함한다. 모델에게 파일을 읽거나 테스트했다고 주장하지 않도록 검토 범위를 명시한다. 일반 CLI의 기존 시작 설정은 로드될 수 있다.

`--from`은 발신 참여자 ID이며 생략 시 `local-agent`다. 다른 AI도 같은 명령을 자신의 ID로 실행할 수 있다. ID는 자기 선언이며 인증 수단은 아니다. `--task`는 기록을 구분하는 업무 ID다. 현재 저장소는 한 공유 협의 세션이므로 서로 무관한 업무의 세션을 격리하는 기능은 제공하지 않는다. 다른 제품의 AI를 호출하는 연결부는 아직 구현하지 않았다.

발신자·업무·메시지 ID는 본문 앞 JSON 머리말로 Claude에게도 전달된다. 대화 폴더의 파일은 전송 로그이며 협업 메시지 양식과 별개다. 로그의 응답 원문은 `reply`, 원 발신자는 `replyFrom`, 대응 요청은 `replyTo`, 기록자는 `recordedBy`로 구분하며 CLI 전달 경로와 세션 ID도 기록한다. 이전 형식의 로그에는 이 추가 필드가 없을 수 있다.

실행 파일은 PATH와 일반 설치 위치에서 탐색한다. 탐색되지 않으면 `CLAUDE_BRIDGE_EXE` 환경변수에 실제 실행 파일 경로를 지정한다. 인증 정보는 이 변수에 넣지 않는다.

기록은 [공유 대화 폴더](../../협의/ai-collaboration/대화/)에 저장한다. 메시지마다 UUID 파일을 만들고 요청·응답 원문과 상태를 보존한다. 세션 상태와 동시에 한 건만 보내기 위한 전송 잠금도 같은 폴더에 둔다. 자동 재시도는 없고 기본 제한 시간은 180초다. API 비용 추정치가 있으면 함께 기록하며 실제 청구액으로 단정하지 않는다.

실패·시간 초과 후에는 대화 기록과 Claude 세션을 확인하고 중복 도달 여부를 판단한 뒤 재전송한다. 첫 호출의 응답이 유실되어 같은 세션 ID가 이미 존재하면 원래 세션 상태를 확인하고 복구해야 한다. 프로세스가 강제 종료되어 잠금이 남으면 해당 전송 프로세스와 세션을 먼저 확인한다. 도구는 잠금을 자동으로 탈취하거나 세션을 초기화하지 않는다.

샌드박스가 서버 접속이나 CLI의 세션 저장을 차단하면 환경의 정식 실행 승인 절차를 사용한다. 네트워크·인증 실패를 응답 성공으로 표시하지 않는다.
