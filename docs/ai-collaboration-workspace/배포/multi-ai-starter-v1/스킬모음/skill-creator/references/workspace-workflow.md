# 워크스페이스 스킬 생성·수정 절차

## 탐색과 선택

1. 워크스페이스 최상위의 `law.md`를 읽는다. 이 문서가 있는 `references/` 디렉터리 기준 `../../..`이 최상위이며, 현재 작업 디렉터리가 하위 폴더여도 바꾸지 않는다. 본문의 프로젝트 경로는 별도 표시가 없으면 이 최상위 기준이다. 문서의 상대 링크는 링크를 포함하는 문서의 디렉터리 기준이다.
2. `<최상위>/스킬모음/`을 실제로 탐색한다. `rg --files --hidden --no-ignore 스킬모음 -g SKILL.md` 또는 아래 catalog 명령을 사용한다. 숨김·gitignore 설정 때문에 파일을 생략하지 않는다. 실행 환경에 제공된 스킬 목록도 별도로 확인한다.
3. 로컬 스킬의 `name`, `description`, 실제 경로를 요청과 대조하고 관련 후보의 본문을 읽는다. 목록이 없거나 오래됐다는 이유로 로컬 스킬이 없다고 결론 내리지 않는다. 읽기 실패·잘못된 메타데이터·링크 문제는 누락시키지 말고 보고하고 해결한다.
4. 생성·수정 요청은 이 로컬 스킬크리에이터를 사용한다. 환경 기본 `skill-creator`와 이름이 같아도 병합되거나 자동으로 우선 선택된다고 가정하지 않는다. 선택한 경로를 명시하고, 환경에서 반드시 적용해야 하는 스킬 지침도 함께 준수한다.
5. ‘자기소개서 쓰는 **스킬을 만들어줘**’는 생성 요청이다. ‘자기소개서를 써줘’는 기존 작성 스킬 활용 요청이다. 키워드만 보고 둘을 혼동하지 않는다. 명시적인 스킬명·경로 지정도 존중한다.

## 생성과 수정

- 기본 목적지는 `<최상위>/스킬모음/<name>/SKILL.md`이다. 전역 홈, 플러그인 캐시, 임시 폴더, 현재 하위 폴더, `.agents/skills`의 복사본을 기본 원본 위치로 사용하지 않는다. 사용자가 다른 목적지를 명시하면 그 위치와 쓰기 권한을 확인한다. 도구가 기본 위치를 강제한다면 아래 명령 대신 직접 파일을 작성하고 검증한다.
- 대화에서 목적과 범위를 파악하고 합리적인 기본값으로 진행한다. 중요한 선택을 좌우하는 정보만 질문한다. 재사용 가능한 자기소개서 스킬을 만드는 데 실제 지원자의 개인정보나 완성된 경력이 반드시 필요한 것은 아니다.
- 폴더명과 `name`은 동일한 1~64자의 소문자 영문·숫자·단일 하이픈 이름으로 정한다. `description`에는 한국어 요청도 대응할 수 있도록 기능과 적용 조건을 구체적으로 쓴다. 본문에는 입력, 수행 방식, 산출물, 품질 확인을 필요한 만큼 담는다. 막연한 범용 설명과 불필요한 부속 파일은 피한다.
- 같은 이름·목적의 기존 스킬을 먼저 확인한다. 기존 스킬 수정은 원래 경로와 이름을 유지하며 원문을 보존한다. 신규 생성 도구는 기존 폴더를 덮어쓰지 않는다. 생성과 수정의 의도가 실질적으로 불명확할 때만 확인한다.
- 필요한 참조·스크립트만 함께 만들고 상대 경로로 연결한다. 실행 환경에 없는 도구, 존재하지 않는 평가기, 유료 API, 네트워크 연결을 기본 작업의 필수 의존성으로 만들지 않는다. 도구 설치나 외부 전송은 별도의 필요성과 권한을 확인한다.

## 실행 도구

아래 명령은 워크스페이스 최상위에서 실행한다. 선택적 실행 도구·테스트는 Node.js 20 이상과 기본 모듈을 사용하며 Python, Claude CLI, npm 설치는 필요 없다. Node.js가 없는 환경에서는 아래 대체 절차를 사용한다. 하위 폴더에서는 최상위로 이동하거나 스크립트까지의 상대 경로를 계산한다. 기본 최상위는 스크립트 위치로 계산하며, 특정 드라이브·사용자 홈·작업 폴더 이름을 저장하지 않는다. 입력 본문 파일과 `--workspace`의 상대 경로는 명령을 실행하는 디렉터리 기준이다.

```text
node "스킬모음/skill-creator/scripts/workspace-skills.mjs" catalog
node "스킬모음/skill-creator/scripts/workspace-skills.mjs" create --name cover-letter --description "자기소개서 작성·수정에 사용한다." --body-file "<임시폴더>/작성한-스킬본문.md"
node "스킬모음/skill-creator/scripts/workspace-skills.mjs" validate
```

`create`는 준비된 UTF-8 본문 파일을 받아 기본 스킬 폴더에 생성하며, 기존 폴더가 있거나 경로가 원본 위치를 벗어나면 실패한다. 본문 파일은 먼저 실제 요청에 맞게 작성해야 한다. 예제 경로를 존재하는 파일처럼 취급하지 않는다. `--workspace`는 격리된 검증용으로만 사용하며 해당 위치에 `law.md`와 `스킬모음/`이 필요하다.

도구를 실행할 수 없다면 파일 탐색·작성·확인을 직접 수행한다. 실행하지 않은 도구 검증을 통과했다고 쓰지 않는다. 도구는 최소 YAML 메타데이터 형식과 파일 구조를 검사하며, 완전한 YAML 구현이나 의미 기반 스킬 선택기가 아니다. 기존 복잡한 메타데이터가 지원 범위를 벗어나면 내용을 임의로 단순화하지 말고 지원하는 검증기로 확인한다.

## 검증과 완료

1. 실제 최종 경로, `name`·`description`, 본문, 상대 참조 파일의 존재, 임시 문구, 중복 이름을 확인한다. 스크립트가 추가되면 실제로 실행한다.
2. 생성을 마친 뒤 다시 catalog를 실행해 새 스킬이 실제 목록에 들어오고 본문을 다시 읽을 수 있는지 확인한다. catalog는 로컬 파일 목록이며 앱의 네이티브 스킬 선택기 등록 성공을 뜻하지 않는다.
3. 요청과 비례한 적용·비적용 사례 및 핵심 품질 조건을 점검한다. 자기소개서 예시라면 ‘스킬 생성’, ‘기존 스킬로 작성’, ‘기존 스킬 수정’을 구분하고 사용자 경력·성과·자격을 지어내지 않는지 확인한다. 구조 검사만으로 실제 AI 선택이나 글의 품질을 검증했다고 주장하지 않는다.
4. 테스트·실행 중간 자료는 격리된 임시 폴더에 만들고 작업 종료 시 정리한다. 삭제 전 실제 경로가 이번 작업의 임시 영역 안에 있는지 확인하며, 사용자의 원본 자료는 삭제하지 않는다. 비교 HTML은 사용자가 지정한 위치에 제공하며, 별도 지정이 없으면 임시 위치를 사용한다. 변경 이력 폴더와 보고서는 사용자가 요청할 때만 만든다. 반복 사용하는 실행 도구·테스트는 해당 스킬 내부에 둔다. `스킬모음/` 아래에 테스트 스킬·이전 버전·평가 워크스페이스를 넣어 탐색 결과를 오염시키지 않는다. 독립 AI 검증은 사용 가능한 도구와 권한이 있을 때만 수행한다.
5. `law.md` 제7조에 따라 모든 변경 지침의 원문·최종문 전체를 포함하는 독립 반응형 비교 HTML을 제공한다. 신규 지침은 ‘변경 전 없음’으로 표시한다. 생성 경로, 수행한 검증과 미검증 범위, 파일 링크를 보고한다. `.skill` 패키지나 브라우저 평가 서버는 요청되거나 실제 필요할 때만 만든다.

## 자동 목록과 직접 탐색의 구분

환경별 자동 스킬 목록에 로컬 스킬이 포함되는지 실제로 확인한다. 포함 여부와 관계없이 `AGENTS.md → law.md → 로컬 직접 탐색 → 해당 SKILL.md 읽기`를 기본 경로로 사용한다. 도구가 다른 시작 지침 파일을 사용하는 경우 해당 파일에서 `law.md`를 읽도록 연결되어 있는지 확인한다. 이는 에이전트가 해당 지침을 읽고 준수한다는 조건에 의존하며 모든 환경의 행동을 강제로 보장하는 장치는 아니다.

`스킬모음/`을 모든 도구의 자동 탐색 경로라고 단정하지 않는다. 자동 등록이 필요하면 대상 도구의 현재 공식 안내에서 탐색 경로·등록 방식과 현재 환경의 쓰기 권한·연결 기능을 확인한 뒤 적용하고 실제 목록에서 검증한다. 읽기 전용이면 원본을 직접 읽는 경로를 사용한다. 운영체제별 연결 방식과 권한이 같다고 가정하거나, 이전 세션의 제약을 현재 환경의 고정 조건으로 사용하지 않는다.

외부 참고: [OpenAI 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills). 외부 출처와 라이선스 URL은 상대 파일 경로로 바꾸지 않는다. 도구별 등록 작업을 할 때 현재 안내를 다시 확인한다.

## 기존 배포본과 고급 평가

LICENSE.txt는 유지한다. 다른 배포본이 안내하는 `eval-viewer/`, `agents/`, `references/schemas.md`, 평가·패키징 스크립트를 이 설치에도 있다고 가정하지 않는다. 고급 평가가 요청되면 실제 파일·도구 가용성을 확인해 구현하거나 이용 가능한 방법으로 평가한다. 없는 파일을 실행하지 않는다.
