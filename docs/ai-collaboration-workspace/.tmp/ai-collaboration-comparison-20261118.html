# 공유 워크스페이스 AI 협업

+7
+8
워크스페이스 최상위 메인지침을 먼저 적용하고, 이 스킬은 AI 사이의 업무 조정에 사용한다. 제품별 고정 서열이나 모든 AI가 같은 도구·기억·권한을 가진다는 가정을 두지 않는다. 사용자 요청과 실행 환경의 권한 범위 안에서 협력한다.

+9
+10
## 1. 참여와 역할 확정

+11
+12
1. 기존 협의 폴더와 현황·결정·미반영 메시지를 읽고 진행 중인 업무와 충돌하는지 확인한다. 처음 시작하면 업무 ID와 공유 폴더를 정한다.

+13
2. 참여자는 고유 참여자 ID, 제품, 실제 세션 식별자(모르면 미확인), 읽기·쓰기·실행·통신 능력과 제약을 스스로 선언한다. 동일 제품의 서로 다른 세션도 다른 참여자다. 타인의 능력은 응답이나 실행 근거 없이 확정하지 않는다.

+14
3. 사용자 지정을 우선하여 조정자·실행자·검토자를 배정하고 당사자의 수락을 기록한다. 조정자는 현황·범위·쟁점·최종 통합을 맡고, 실행자는 배정된 산출물을 작성하며, 검토자는 결과와 검증 근거를 확인한다. 인원이 부족하면 겸임을 명시하고 독립 검토로 표현하지 않는다.

+15
4. 목표, 산출물, 완료 조건, 범위와 제외 범위, 참여자, 파일별 작성자, 의존 관계, 검증 담당, 합의가 필요한 결정의 참여자, 재시도 한도와 승계 조건을 현황에 기록한다. 양식은 [협업 기록 양식](references/coordination-records.md)을 사용한다.

+16
+17
## 2. 연락 방식과 메시지

+18
+19
- 실제 가능한 공유 파일·CLI·API·사용자 중계 중 최소한의 방식을 선택한다. 연결 도구가 있어도 상대 세션이 실행 중인지, 기존 세션인지 새 세션인지 확인한다. 파일을 만들었다는 사실만으로 상대가 읽었거나 답할 수 있다고 간주하지 않는다.

+20
- 사용자에게 이미 승인받은 연결과 업무 범위에서는 재승인을 반복하지 않는다. 새 외부 전송·비용·권한이 기존 범위를 벗어나면 필요한 확인을 한다. 호출에 필요한 맥락만 전달하며 비밀정보를 보내지 않는다.

+21
- 공유 파일 메시지는 참여자별 폴더에 **1메시지 1신규 파일**로 기록한다. ID는 참여자 ID와 UUID 등 중앙 발급 없이 중복을 피하는 값의 조합으로 만든다. 재시작으로 초기화될 수 있는 단순 일련번호만을 ID로 삼지 않는다. 타인의 원문은 수정하지 않고 정정은 새 메시지로 남긴다.

+22
- 업무 ID, 메시지 ID, 발신자·수신자, 유형, 회신 대상 ID, 시각, 본문을 포함한다. 시각은 참고 정보이며 선점 권한의 근거로 쓰지 않는다.

+23
- 쓰기가 불가능한 참여자의 응답은 중계자가 원문을 바꾸지 않고 대리 기록한다. 원 발신자와 기록자를 별도 필드로 구분하고 전달 경로와 실제 세션을 남긴다. 요약·해석은 중계자 자신의 새 메시지로 기록한다.

+24
- `ack`는 수신 확인이다. `proposal`은 제안, `decision`은 특정 제안에 대한 동의·반대·보류, `result`는 수행 결과, `handoff`는 인계다. 각 decision은 제안 ID와 버전을 지정한다. 필요한 참여자 전원이 같은 버전에 명시적으로 동의한 경우만 합의로 표시한다. 내용이 바뀌면 영향을 받는 참여자의 재동의를 받는다.

+25
- 자동 재시도 기본값은 **0회**다. 실패·시간 초과는 기록하고 응답 대기로 둔다. 요청이 실제 도달했는지 불명확하면 세션과 기록을 먼저 확인하여 중복 전송을 피한다. 자동 재시도가 필요하면 횟수와 중복 방지 방법을 사전에 합의한다. 무한 폴링이나 무응답에 의한 승인을 사용하지 않는다.

+26

## 3. 분담과 동시 수정

+28
+29
파일별 단일 작성자를 기본으로 하며 독립적인 범위만 병렬 실행한다. 현황 파일은 조정자 한 명이 갱신하고 마지막으로 반영한 메시지 ID 목록을 남긴다. 참여자는 그 이후 메시지도 확인한다. 현황에 적힌 담당은 협업 약속이며 OS 잠금이나 접근 권한을 보장하지 않는다.

+30
+31
쓰기 직전에 대상 파일을 다시 읽고 기준 내용과 달라졌으면 해당 쓰기를 멈춘다. 타인의 변경을 덮어쓰거나 되돌려 충돌을 해결하지 않는다. 공통 파일이 추가로 필요하면 조정자가 작성자와 순서를 정한 뒤 진행한다. 직접 공동 편집이 필요하면 파일 내 범위와 통합 담당을 먼저 합의한다.

+32
+33
조정자나 파일 담당이 동시에 선언되면 사용자 지정 → 기존 명시적 합의 순서로 확인한다. 해결되지 않으면 해당 범위 쓰기를 보류하고 사용자에게 결정할 쟁점을 설명한다. 타임스탬프·모델명·다수결로 임의의 승자를 정하지 않는다. 충돌과 독립적인 작업은 계속할 수 있다.

+34
+35
## 4. 회의와 결정

+36
+37
조정자는 현재 결정할 쟁점과 필요한 참여자를 지정하고, 참여자는 근거와 대안을 제안한다. 결정에는 채택 내용, 근거, 동의한 메시지 ID, 보류 또는 미해결 사항을 기록한다. 합의된 주제는 새로운 근거·요구 변경·검증 실패가 있을 때 재논의한다.

+38
+39
단순 접속 성공, 모델의 일반적인 찬성, 조정자의 요약만으로 최종 산출물까지 승인받았다고 표현하지 않는다. 실제 참여자·검토한 버전·직접 실행 여부를 구분한다. 사용자 의도나 중요한 설계를 바꾸는 미해결 쟁점은 사용자에게 확인한다.

+40
+41
필수 동의자가 이탈하여 합의 요건을 충족할 수 없으면 사용자에게 대체 참여자 또는 결정 방법을 요청한다. 남은 참여자끼리 동의 요건을 임의로 축소하지 않는다.

+42
+43
## 5. 합류·연락 두절·인계

+44
+45
- 새 AI는 능력 선언 후 현황과 기존 결정을 읽고 배정·수락을 거쳐 참여한다. 진행 중인 파일을 인계 없이 수정하지 않는다. 사용자 요청이 없는 AI 세션 생성이나 호출을 이 스킬 자체가 허가하지는 않는다.

+46
- 연결 실패나 상대 미기동은 응답 대기로 기록한다. 필요한 경우 다음 보고에서 실행·연결에 필요한 조치를 알린다. 배정된 독립 작업은 계속하며, 무응답만으로 타인의 파일을 인수하지 않는다.

+47
- 승계는 사용자 지정 또는 사전 합의된 대체 절차로 진행한다. 후임이 인수를 수락한 뒤 실제 파일·미반영 메시지·검증 결과를 대조하여 현황을 갱신한다. 기존 조정자는 복귀 시 변경된 체제를 확인하고 배정을 따른다. 두 사람이 동시에 현황을 쓰지 않는다.

+48
- 인계에는 현재 단계, 완료한 일, 다음 행동, 담당자, 수정 범위, 파일의 기준 상태, 마지막 검증 명령·결과, 미해결 쟁점을 담는다. 재시작한 AI는 기억 대신 이 기록과 실제 파일을 다시 읽는다.

+49
+50
## 6. 검토와 완료

+51
+52
실행자는 변경 파일과 검증 명령·결과·환경·대상 상태를 보고한다. 검토자는 실제 최종 내용과 근거를 확인하고 가능하면 관련 검증을 재현한다. 읽기 전용 또는 대화 전용 참여자의 검토는 내용 검토로 명시한다.

+53
+54
작성자의 통과 보고와 현재 파일에서 재현된 실패가 충돌하면 실패 근거를 확인하고 동일 조건으로 재검증한다. 해결 전 완료 처리하지 않는다. 조정자는 최종 파일, 미해결 쟁점, 필요한 동의, 완료 조건을 대조하여 결과를 보고한다. 구조 검사 통과, 실제 실행 성공, 독립 검토, 도구 자동 등록을 서로 구분하며 미검증 범위를 밝힌다.

## 적용 점검

+63
+64
- 세 번째 AI가 합류: ID와 실제 능력을 선언하고 현황·기존 결정 확인 → 범위 배정과 수락 → 인계받은 범위만 수정.

+65
- 공통 파일 필요: 해당 쓰기는 보류하고 단일 작성자와 순서 확정 → 독립 작업은 계속.

+66
- 조정자 두절: 자기 메시지에 대기 상태 기록 → 기존 독립 작업 계속 → 사용자 지정/사전 합의에 따라 후임 수락 후 승계.

+67
- 검토 실패: 명령·환경·파일 상태 기록 → 현재 최종 파일로 재현 → 수정과 재검증 후 완료 판단.

+68
- 단일 AI 작업: 다른 참여자가 필요한 요청이 아니면 협업 역할과 회의를 새로 만들지 않음.

# Claude 연결 도구

+2
+3
Node.js와 설치·인증된 Claude Code CLI를 사용한다. 추가 패키지와 API 키 파일은 만들지 않는다. 명령은 워크스페이스 최상위 기준이다.

`send`는 UTF-8 메시지 파일을 읽어 CLI의 표준 입력으로 전달한다. 메시지를 셸 명령으로 해석하지 않는다. 최초 호출에서 전용 세션 ID를 만들고 성공한 이후에는 명시적 `--resume`으로 같은 세션을 이어간다. 현재 열려 있는 다른 Claude 창과 동일한 세션을 제어하는 도구는 아니다.

+14
+15
연결은 [프로그램 방식 실행 공식 안내](https://code.claude.com/docs/en/headless)를 따르며, CLI의 기존 인증과 조직 정책을 사용한다. 권한 우회 옵션은 사용하지 않는다. 대화용 호출에 내장 도구와 MCP 서버를 제공하지 않으므로 검토할 파일 본문과 검증 결과를 메시지에 직접 포함한다. 모델에게 파일을 읽거나 테스트했다고 주장하지 않도록 검토 범위를 명시한다. 일반 CLI의 기존 시작 설정은 로드될 수 있다.

+16
+17
`--from`은 발신 참여자 ID이며 생략 시 `local-agent`다. 다른 AI도 같은 명령을 자신의 ID로 실행할 수 있다. ID는 자기 선언이며 인증 수단은 아니다. `--task`는 기록을 구분하는 업무 ID다. 현재 저장소는 한 공유 협의 세션이므로 서로 무관한 업무의 세션을 격리하는 기능은 제공하지 않는다. 다른 제품의 AI를 호출하는 연결부는 아직 구현하지 않았다.

+18
+19
발신자·업무·메시지 ID는 본문 앞 JSON 머리말로 Claude에게도 전달된다. 대화 폴더의 파일은 전송 로그이며 협업 메시지 양식과 별개다. 로그의 응답 원문은 `reply`, 원 발신자는 `replyFrom`, 대응 요청은 `replyTo`, 기록자는 `recordedBy`로 구분하며 CLI 전달 경로와 세션 ID도 기록한다. 이전 형식의 로그에는 이 추가 필드가 없을 수 있다.

+20
+21
실행 파일은 PATH와 일반 설치 위치에서 탐색한다. 탐색되지 않으면 `CLAUDE_BRIDGE_EXE` 환경변수에 실제 실행 파일 경로를 지정한다. 인증 정보는 이 변수에 넣지 않는다.

+23
기록은 [공유 대화 폴더](../../협의/ai-collaboration/대화/)에 저장한다. 메시지마다 UUID 파일을 만들고 요청·응답 원문과 상태를 보존한다. 세션 상태와 동시에 한 건만 보내기 위한 전송 잠금도 같은 폴더에 둔다. 자동 재시도는 없고 기본 제한 시간은 180초다. API 비용 추정치가 있으면 함께 기록하며 실제 청구액으로 단정하지 않는다.

+25
실패·시간 초과 후에는 대화 기록과 Claude 세션을 확인하고 중복 도달 여부를 판단한 뒤 재전송한다. 첫 호출의 응답이 유실되어 같은 세션 ID가 이미 존재하면 원래 세션 상태를 확인하고 복구해야 한다. 프로세스가 강제 종료되어 잠금이 남으면 해당 전송 프로세스와 세션을 먼저 확인한다. 도구는 잠금을 자동으로 탈취하거나 세션을 초기화하지 않는다.

+27
샌드박스가 서버 접속이나 CLI의 세션 저장을 차단하면 환경의 정식 실행 승인 절차를 사용한다. 네트워크·인증 실패를 응답 성공으로 표시하지 않는다.
