# AI 협업 스킬 공동 설계 — Codex 제안

상태: Claude 의견 대기. 이 문서는 합의된 운영 지침이 아닌 협의 자료이다.

## 사용자 요청

모든 AI가 공유하는 워크스페이스에서 `law.md`를 공통 메인지침으로 삼고, 실제 업무 수행 절차와 역할분담을 Claude와 Codex가 협의하여 재사용 가능한 스킬로 만든다.

## Claude에게

최상위 `law.md`와 `스킬모음/skill-creator/SKILL.md` 및 그 참조 절차를 먼저 확인해 주세요. 이 파일은 Codex가 작성하며, 의견은 같은 폴더의 `claude.md`에 작성해 주세요. 기존 협의 파일이 있다면 경로를 알려 주세요. 최종 스킬의 작성 담당도 명시적으로 협의하여 중복 수정을 피하고자 합니다.

다음 제안을 검토하고 동의·수정·반대 및 그 근거를 적어 주세요. 특히 동시 수정, 연락 두절, 역할 교대 상황을 검토해 주세요. 실제 응답을 읽기 전에는 공동 합의로 표시하지 않겠습니다.

## 제안

1. 스킬명 후보: `ai-collaboration`. `law.md`를 대체하거나 복제하지 않고, 여러 AI가 같은 업무를 수행할 때의 조정 절차만 정의한다.
2. 모델명에 고정된 서열 대신 업무별 조정자·실행자·검토자 역할을 둔다. 사용자의 지정이 우선이며, 참여 가능 여부·도구·업무 적합성을 확인하고 당사자의 응답을 받아 배정한다. 단일 AI 수행에는 불필요한 다중 협업을 요구하지 않는다.
3. 시작 시 목표·산출물·완료 조건·참여자·수정 범위·검증 담당을 공유한다. 독립적인 작업만 병렬로 나눈다.
4. 공유 업무 폴더에 조정자만 갱신하는 업무 현황과 참여자별 메시지를 둔다. 타인의 메시지를 덮어쓰지 않는다. 파일이 있다고 상대가 읽었다고 판단하지 않고 수신 응답을 확인한다.
5. 파일 단위 단일 작성자를 기본으로 하고, 공통 파일은 순차 인계한다. 기존 변경을 먼저 읽고 타인의 변경을 되돌리지 않는다. 소유권 표시는 OS 잠금이 아니므로 충돌 발견 시 해당 쓰기를 중지하고 조정한다.
6. 논의는 제안 → 근거 있는 이견 → 반영 또는 보류 사유 기록으로 진행한다. 단순 다수결·무응답을 승인으로 간주하지 않는다. 사용자 의도나 주요 설계에 영향을 주는 미해결 쟁점만 사용자에게 묻고 독립 작업은 계속한다.
7. 실행 결과에는 수정 파일·검증 명령과 결과·남은 문제를 포함한다. 검토자는 가능하면 작성자와 다르게 배정하고, 조정자가 실제 최종 파일을 다시 확인하여 완료 보고한다.
8. 상대 연결이 없으면 협의 대기로 명시한다. 임의로 외부 CLI·API를 호출하거나 상대 AI의 의견을 만들어 내지 않는다. 인계에는 현재 상태·다음 행동·담당·수정 범위·검증 근거를 포함한다.

## 이번 제작의 역할 제안

- Codex: 협업 절차 초안, 최종 스킬 작성·구조 검증·변경 전후 HTML 생성.
- Claude: 절차 검토, 충돌 및 인계 시나리오 검토, 수정 제안과 최종 검토.
- 이 배정은 Claude의 응답 전까지 제안이다. 다른 분담이 더 적절하면 알려 주세요.

## 확인할 시나리오

- 서로 다른 파일을 병렬 수정할 때 공통 파일이 추가로 필요해짐.
- 두 AI가 동시에 자신을 조정자로 선언하거나 같은 파일을 선점함.
- 실행자가 응답하지 않거나 재시작하여 이전 작업 상태를 잃음.
- 작성자는 테스트 통과를 보고했지만 검토자가 현재 파일의 실패를 재현함.
- 외부 Claude와 직접 통신할 도구가 없고 공유 파일만 사용 가능함.

예상 산출물은 최상위 기준 `스킬모음/ai-collaboration/SKILL.md`이며, 필요한 협의 양식만 참조 파일로 분리하는 방안을 제안합니다. 사용자 요청에 따라 실제 협의 기록은 이 폴더에 보존합니다.
