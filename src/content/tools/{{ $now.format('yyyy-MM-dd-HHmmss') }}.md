## 한 줄 요약
프롬프트나 모델을 변경했을 때 시스템이 망가지지 않도록 사전 정의된 데이터셋과 기준으로 품질을 자동 검증하는 과정입니다.

## 이게 뭔가요?
전통적인 소프트웨어의 단위 테스트(Unit Test)처럼, 생성형 AI 시스템이 의도한 형식과 품질로 일관되게 응답하는지 점검하는 절차입니다. 보통 'LLM Evals(평가)'라고 부릅니다.

프롬프트 수정, 모델 파라미터 변경, 신규 모델 도입 시 기존에 잘 되던 기능이 오작동하는 회귀(Regression) 현상을 사전에 방지하기 위해 수행합니다.

## 이렇게 활용해보세요
1. **골든 데이터셋(Golden Dataset) 구축**: 서비스 핵심 시나리오를 반영하는 대표 질문과 기대 답변 세트를 30~50개 정도 수집해 기준점을 잡습니다.
2. **규칙 기반 테스트 적용**: JSON 스키마 준수 여부, 필수 키 포함 여부, 글자 수 제한 등 결정론적인 규칙을 코드 레벨에서 우선 검증합니다.
3. **LLM-as-a-Judge 활용**: 정량적 검증이 어려운 톤앤매너나 답변 완성도는 상위 모델(예: GPT-4o, Claude 3.5 Sonnet)을 채점관으로 지정해 루브릭 기반으로 점수화합니다.
4. **CI/CD 파이프라인 연동**: 프롬프트를 코드로 관리하고, 깃허브 액션(GitHub Actions) 등을 통해 변경 사항 발생 시 자동으로 테스트 스위트를 실행하도록 파이프라인을 구성합니다.

## 주의할 점
- 채점용 LLM 역시 편향이나 비결정적 오류가 발생할 수 있으므로, 복잡한 로직은 정기적인 수동 샘플링 검수(Human-in-the-loop)를 병행해야 합니다.
- 초기부터 수천 개의 테스트 케이스를 돌리면 API 비용과 지연 시간이 급증하므로, 실패 비용이 큰 핵심 유저 플로우부터 단계적으로 테스트 범위를 확장하세요.
