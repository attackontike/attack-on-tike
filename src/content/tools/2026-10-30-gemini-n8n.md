## 한 줄 요약
n8n의 워크플로우에 Gemini API를 연결하여 주제 선정부터 텍스트 생성, CMS 업로드까지 전 과정을 자동화하는 시스템입니다.

## 이게 뭔가요?
오픈소스 기반 워크플로우 자동화 도구인 **n8n**과 구글의 대규모 언어 모델 **Gemini API**를 결합한 콘텐츠 파이프라인입니다. 

Zapier나 Make 같은 서비스에 비해 n8n은 자체 호스팅이 가능해 비용 효율성이 높고 데이터 보안에 유리합니다. 여기에 가성비와 처리 속도가 우수한 Gemini를 연동하면, 정해진 스케줄이나 특정 트리거(스프레드시트 입력, RSS 피드 등)에 따라 콘텐츠를 자동으로 가공하고 워드프레스나 고스트(Ghost), 정적 사이트(GitHub) 등으로 직접 전송할 수 있습니다.

## 이렇게 활용해보세요

1. **기반 환경 준비하기**
   - n8n 환경(Cloud 또는 Docker 자체 호스팅)을 준비합니다.
   - Google AI Studio에서 Gemini API 키를 발급받고, 연동할 웹사이트의 API 키(예: 워드프레스 Application Password, Ghost Admin API)를 준비합니다.

2. **트리거 및 입력 노드 구성**
   - `Schedule Trigger` 노드로 발행 주기(예: 매일 오전 9시)를 설정하거나, `Google Sheets` 노드로 미리 적어둔 주제 목록을 한 행씩 가져옵니다.

3. **Gemini 노드로 본문 생성**
   - n8n의 기본 `Google Gemini` 노드 또는 `HTTP Request` 노드를 추가합니다.
   - 프롬프트에 역할, 글 톤앤매너, 구조(Markdown 또는 HTML 포맷 지정)를 명확히 정의하여 본문 작성을 요청합니다.

4. **웹사이트 배포 노드 연결**
   - CMS에 맞는 노드(WordPress 노드 등)를 추가하고, 이전 단계에서 생성된 텍스트와 제목을 매핑합니다.
   - 첫 테스트 시에는 바로 발행하기보다 `status: draft`(임시저장)로 지정해 결과물을 검토할 수 있도록 설정합니다.

## 주의할 점

- **Human-in-the-loop(검수 단계) 유지**: 생성형 AI 특유의 환각(Hallucination) 현상이 발생할 수 있습니다. 처음부터 100% 자동 발행으로 두기보다는 CMS의 임시글 상태로 저장한 뒤 검수 후 발행하는 방식을 권장합니다.
- **API 사용량 및 에러 핸들링**: Gemini API의 분당 요청 제한(Rate Limit)에 걸리지 않도록 n8n 워크플로우 내에 적절한 대기 시간(`Wait` 노드)을 두거나 에러 발생 시 재시도 로직을 설계해야 합니다.
- **SEO 및 검색엔진 페널티**: 동일한 패턴으로 대량 생성된 저품질 콘텐츠는 검색엔진 노출에 불리할 수 있습니다. 메타데이터 생성, 고유한 사례 추가 등 프롬프트의 품질을 꾸준히 고도화해야 합니다.
